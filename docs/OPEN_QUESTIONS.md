# Open questions

Unresolved design and implementation questions, with their impact and the suggested next
investigation. Close one by linking the ADR or commit that settles it.

| # | Question | Impact | Next step |
|---|---|---|---|
| OQ-1 | **What does the knowledge-assimilation report recommend?** It was unreachable from the build environment (DISCOVERY §1). The learning design (ADR-0009: observed/self-reported/inferred, generative prompts, no flashcards, expanding revisits, sessions) may conflict with it. | High for the learning half | Allow `xyz.tabdump.xyz` in the session's network settings (or paste the report); compare its recommendations against ADR-0009 and the reader's flows; supersede ADRs where it disagrees. |
| OQ-2 | **Does the research protocol produce good results when run unattended by a headless agent?** In this session the demo research runs were performed by Claude Code interactively, because launching a nested autonomous agent was blocked by the session's safety policy. Scheduled runs were exercised with a stand-in agent. | High | In ai-box: `kw schedule run-now <topic>` with Claude and with Codex; read the run reports and the kb diff; tighten `research-run.md` where agents drift (e.g. skipping `kw run end`, paraphrased quotes). |
| OQ-3 | **Codex specifics**: does Codex load the skills and follow `kw` exit codes the same way? Do `codex exec --json` usage events match what `runs.read_usage` parses (`turn.completed`)? | Medium | One Codex run in a box; adjust `read_usage` to the actual event names. |
| OQ-4 | **Colliding schedules.** All topics share one orchestrator workdir, so a firing that lands during another topic's run fails (logged as an error in `cron.<slug>.log`, not a clean SKIP) and waits for the next firing. | Low–medium | Either stagger crons (current advice), or teach run-scheduled.sh to treat "workdir busy" as SKIP (small ai-box change), or give each topic its own workdir and rely on flock (loses whole-run isolation). |
| OQ-5 | **Quote verification on PDFs.** pdftotext layout (ligatures, hyphenation, columns) can make verbatim quotes fail; the agent then uses `--allow-unverified`, which weakens provenance. | Medium | Normalize ligatures (ﬁ→fi) and soft hyphens in `normalize_for_match`; test on real papers. |
| OQ-6 | **Learning-state versioning and backup.** `learning/` isn't in git. | Medium | Optional `kw learn snapshot` (commit to a separate private repo), or document a backup routine. |
| OQ-7 | **When do concepts deserve their own note?** Concepts are created by agents; quality varies with the agent. Too many weak concepts would dilute the reader. | Medium | After a few real topics, add a consolidation check for thin concepts (no claims, short explanation) and duplicate concepts across topics. |
| OQ-8 | **Prompt injection beyond text.** The reader escapes everything and the CLI marks text untrusted, but an agent reading a hostile page still runs with bypassed permissions and can reach `/knowledge` and its own home. | High (inherited from ai-box's design) | Consider a separate low-privilege research box without GitHub credentials for scheduled research; or restrict scheduled runs to an allowlist of domains. |
| OQ-9 | **What counts as "important" for notifications?** Agents decide `--notify`; the only automatic ones are low-yield and "no further runs". | Low | Collect a few weeks of notifications and tune the skill's guidance. |
